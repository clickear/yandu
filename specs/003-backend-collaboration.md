# 003 · 服务端与团队协作

状态：DDD 技术设计已形成；服务端实现进行中，完整产品决策与验收仍待完成。详细设计见[言渡服务端 DDD 技术设计](../docs/ddd-technical-design.md)，执行计划见[003 实施计划](../plans/003-backend-collaboration.md)。

本规格细化 `GOAL.md` 的 G1–G4 目标，不代表其中尚未验证的能力已经交付。当前 React + TypeScript 原型继续作为产品交互基线；后端实现需使用真实 API 与数据库，不得在前端伪造登录、多人协作、导入完成或发布成功状态。

## 产品范围

首期范围：项目成员与角色权限（暂不引入租户/组织隔离）、项目和语言、命名空间与源词条、译文协作与审核、占位符/必填校验、术语与翻译记忆建议、JSON 导入预览和异步导入、质量门禁、不可变发布版本、JSON 与 Java Properties 导出、历史回溯、审计与运维所需的健康/任务状态接口。

不纳入首期：截图/OCR 翻译、计费商城、默认绑定机器翻译厂商、微服务拆分、跨区域主动-主动部署。机器翻译与 Git 集成保留端口，不阻断人工翻译闭环。

## DDD 规则摘要

- 组织、项目、目录/词条、译文、导入任务、发布版本分别有清晰生命周期；不以一个巨型 `Project` 聚合承载所有词条和译文。
- `CatalogEntry` 管源文本与单调递增的源版本；每个 `(entry, targetLocale)` 对应独立 `Translation` 聚合，含翻译状态、审核状态和乐观锁版本。
- 任一源文本变更使该词条全部目标译文转为 `NEEDS_REVIEW`，并留下源版本变更事件；译文更新必须带期望版本，冲突返回可恢复的 409。
- 审核是针对具体译文版本的不可变决定；被编辑的新版本撤销原审核有效性，审核人不能审核自己的译文（管理员代审需明确审计原因）。
- 发布版本是不可变快照，记录词条源版本、译文版本、质量报告、操作者与资源校验和；回滚创建指向旧内容的新发布，不改写历史。
- 每个命令先验证项目成员权限和领域不变量；本期没有组织租户上下文，不接受客户端伪造租户 ID 来代替授权。

## 当前后端实现范围

当前代码建立了通用 OIDC JWT 身份解析、项目成员角色授权、Workspace、Catalog、Translation、Import、Release 和 AuditLog 模块及 `/api/v1` REST API。前端支持显式 API 模式、OIDC 登录、项目与成员管理、分页译文加载、服务端保存/送审/审核、失败草稿恢复、源文修改/历史/归档、项目术语管理与翻译记忆建议、JSON 差异预览与异步导入、JSON/Java Properties 发布下载；未配置服务端时保留本地原型。服务端提供公开的 liveness/readiness 健康探针，readiness 检查 MySQL 连通性且不公开组件详情。仍缺少完整质量规则/模板格式支持、本地数据迁移包和正式故障恢复演练。真实 MySQL 8 集成迁移和端到端业务链尚未验证。租户模式和 Outbox 本期不实现。

工程取舍：优先沿现有模块扩展，不为单一小操作拆出一组类型或单独测试类。用例验证按大模块集中执行；小改动先做编译和差异检查，避免频繁运行全套测试。

## 验收编号

本规格验收编号供计划、PR、测试和验收记录引用。

| 编号 | 可验收行为 |
| --- | --- |
| B01 | 用户认证后仅能访问其项目成员范围；所有资源查询、写入、导出、历史读取均验证项目权限。（组织/租户隔离暂不在本期验收。） |
| B02 | 管理员可创建项目并配置源语言/目标语言；项目内命名空间与词条可检索、分页和归档。 |
| B03 | 词条源文变更生成新源版本，相关译文进入待复核；历史源文可查询。 |
| B04 | 译员保存译文后可重新读取；网络失败有草稿恢复；版本过期写入返回冲突，不静默覆盖。 |
| B05 | 审核仅针对当前译文版本；编辑使审核失效；未经授权的审核命令拒绝并留审计记录。 |
| B06 | 占位符和必填规则可定位到词条与语言；质量错误阻止发布，警告按项目策略处理。 |
| B07 | JSON 导入先解析并生成差异预览；非法文件不部分写入；同一幂等键重复提交不重复创建数据。 |
| B08 | 发布仅消费审核通过且质量门禁通过的指定版本；发布包不可变，可再次下载并校验一致。 |
| B09 | Java Properties 的编码、转义、Unicode 和注释策略有 fixtures；其正式支持范围按格式规格确定。 |
| B10 | 项目成员/角色变更、导入、词条源文编辑、审核、发布、回滚均可审计。 |
| B11 | 数据迁移可升级和回滚；备份恢复、任务失败重试与健康/错误观测有演练证据。 |
| B12 | 本地原型可通过显式迁移包导入服务端；迁移前可预览冲突，重复提交安全。 |

## 阶段门槛

- **阶段 A（产品和接口）**：确认身份提供方、项目权限矩阵、状态机、格式范围、迁移策略；租户隔离与 Outbox 本期明确排除；发布 OpenAPI 草案和 ADR。B01、B05、B06、B08 的规则需产品确认。
- **阶段 B（持久化和迁移）**：真实数据库迁移、组织/项目/词条 API、访问控制、前端数据适配器和原型迁移；通过 B01–B04、B12 对应集成测试。
- **阶段 C（协作和交付）**：译文、校验、术语/记忆、异步导入、发布与历史；通过 B05–B10 对应集成测试。
- **商业试用门**：B01–B12 都有真实执行证据，并满足 `GOAL.md` 的并发、性能、安全、运维与恢复门槛。设计文档、模拟数据或单元测试不能替代端到端证据。

## 未决产品决策

1. 身份提供方、组织创建/邀请方式、管理员恢复流程与用户删除/数据保留策略。
2. Owner/Admin/Translator/Reviewer/Viewer 权限矩阵，审校自审与管理员代审规则，审核撤回机制。
3. 目标语言级别或项目级角色；用户是否可同时承担译员与审校员角色。
4. 嵌套 JSON、扁平 JSON、ICU、Java Properties 的正式范围、编码/转义规则及单项目文件限制。
5. 质量规则、占位符语法、警告是否可发布、术语匹配与翻译记忆可见范围。
6. 源文变更后发布/审核失效规则，回滚的权限和是否需要再次审批。
7. 部署地域、对象存储、邮件、备份保留期、密钥托管和灾难恢复负责人。

## 验证要求

真实 MySQL 8.0 集成测试、API 契约测试、跨项目越权测试、乐观锁冲突测试、导入幂等测试、发布门禁与不可变快照测试、格式 fixtures、迁移前后兼容测试，以及一次实际备份恢复演练。租户模式启用前再增加跨组织隔离测试。若宣称可切换至另一数据库，还必须对目标数据库运行同一持久化契约测试。规模基准按 `GOAL.md` 记录；组织隔离项待租户阶段再验收。
