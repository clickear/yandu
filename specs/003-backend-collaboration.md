## 产品范围

首期范围：项目成员与角色权限（暂不引入租户/组织隔离）、项目和语言、命名空间与源词条、译文协作与审核、占位符/必填校验、术语与翻译记忆建议、JSON 导入预览和异步导入、质量门禁、不可变发布版本、JSON 与 Java Properties 导出、历史回溯、审计与运维所需的健康/任务状态接口。

不纳入首期：截图/OCR 翻译、计费商城、默认绑定机器翻译厂商、微服务拆分、跨区域主动-主动部署。机器翻译与 Git 集成保留端口，不阻断人工翻译闭环。

## DDD 规则摘要

- 组织、项目、目录/词条、译文、导入任务、发布版本分别有清晰生命周期；不以一个巨型 `Project` 聚合承载所有词条和译文。
- `CatalogEntry` 管源文本与单调递增的源版本；每个 `(entry, targetLocale)` 对应独立 `Translation` 聚合，含翻译状态、审核状态和乐观锁版本。
- 任一源文本变更使该词条全部目标译文转为 `NEEDS_REVIEW`，并留下源版本变更事件；译文更新必须带期望版本，冲突返回可恢复的 409。
- 审核是针对具体译文版本的不可变决定；被编辑的新版本撤销原审核有效性，审核人不能审核自己的译文（管理员代审需明确审计原因）。
- 发布版本是不可变快照，记录词条源版本、译文版本、质量报告、操作者与资源校验和；回滚创建指向旧内容的新发布，不改写历史。
- 每个命令先验证项目成员权限和领域不变量；本期没有组织租户上下文，不接受客户端伪造租户 ID 来代替授权。
- 项目成员在整个项目内仅有一个角色；Owner/Admin 管理设置，Translator 编辑译文并送审，Reviewer 审核，Viewer 只读；Admin 不能管理 Owner/Admin，Owner 只能转让给现有 Admin。
- 项目、语言、命名空间和词条可恢复归档且不硬删除；源语言不可改，目标语言可归档但至少保留一个启用目标语言。旧发布保持不可变并继续供有权限成员下载。
- 词条键在项目范围唯一，命名空间只是分组。显式改键/移动保留词条 ID、译文状态和源修订；扁平文件导入不推测改键。
- 首期质量规则只接受命名占位符 `{name}`，按名称和次数精确对比；`{{`/`}}` 是字面花括号，不支持的花括号格式视为错误。错误阻止送审和发布，但允许保存草稿。
- 扁平 UTF-8 JSON 是导入格式；扁平 JSON 和 Java Properties 是发布格式。Properties 只导出，稳定排序并转义为 ASCII，不保留注释。
- 术语和翻译记忆属于独立语言知识模块且按项目隔离；记忆建议限同项目当前源版本的已审核完全匹配结果，仅供选择，不自动写入。

## 当前后端实现范围

当前代码建立了通用 OIDC JWT 身份解析、项目成员角色授权、Workspace、Catalog、Translation、Import、Release、AuditLog 模块及 `/api/v1` REST API。前端支持显式 API 模式、OIDC 登录、项目与成员管理、服务端译文工作流、源文修改/历史/归档、术语与翻译记忆建议、JSON 差异预览与异步导入、JSON/Java Properties 发布下载；未配置服务端时保留本地原型。已加入版本 1 的本地项目迁移包预览、确认、幂等异步分批迁移、进度和本地/服务端词条 ID 映射查询，以及迁移失败后同包重试；迁移期间项目保持隐藏。服务端提供公开 liveness/readiness 探针，readiness 检查 MySQL 连通性且不公开组件详情。真实 MySQL 8 集成迁移和 UI→OIDC→API→MySQL 端到端链路尚未验证，正式故障恢复演练未完成。租户模式和 Outbox 本期不实现。

工程取舍：优先沿现有模块扩展，不为单一小操作拆出一组类型或单独测试类。用例验证按大模块集中执行；小改动先做编译和差异检查，避免频繁运行全套测试。

## 验收编号

本规格验收编号供计划、PR、测试和验收记录引用。

| 编号 | 可验收行为 |
| --- | --- |
| B01 | 用户认证后仅能访问其项目成员范围；所有资源查询、写入、导出、历史读取均验证项目权限。（组织/租户隔离暂不在本期验收。） |
| B02 | 管理员可创建项目并配置源语言/目标语言；项目内命名空间与词条可检索、分页和归档。 |
| B03 | 词条源文变更生成新源版本，相关译文进入待复核；历史源文可查询。 |
| B04 | 译员保存译文后可重新读取；网络失败有草稿恢复；版本过期写入返回冲突，不静默覆盖。 |
| B05 | 审核仅针对当前译文版本；编辑使审核失效；未经授权的审核命令拒绝并留审计记录。 |
| B06 | `{name}` 命名占位符和必填规则可定位到词条与语言；质量错误阻止送审和发布，允许保存草稿。 |
| B07 | JSON 导入先解析并生成差异预览；非法文件不部分写入；同一幂等键重复提交不重复创建数据。 |
| B08 | 发布仅消费审核通过且质量门禁通过的指定版本；发布包不可变，可再次下载并校验一致。 |
| B09 | Java Properties 仅用于导出；采用稳定键顺序和 ASCII Unicode 转义，不承诺保留注释；格式 fixtures 验证消费端读取。 |
| B10 | 项目成员/角色变更、导入、词条源文编辑、审核、发布、回滚均可审计。 |
| B11 | 数据迁移可升级和回滚；备份恢复、任务失败重试与健康/错误观测有演练证据。 |
| B12 | 本地原型可通过显式迁移包导入服务端；迁移前可预览冲突，重复提交安全。 |

### B12 本地项目迁移约定

- 迁移包为 UTF-8 JSON，`format` 固定为 `yandu-project-migration`，`schemaVersion` 为 `1`；一次仅迁移一个项目，包含项目名称、说明、源语言、目标语言和词条/各语言译文。
- 预览校验包大小不超过 5 MiB、词条数不超过 10,000、语言和词条规则符合当前服务端约束，并返回名称冲突及可修正的目标项目名称。
- 应用始终创建新服务端项目；服务端重新生成所有数字 ID。词条键冲突或格式错误拒绝整个包，不自动覆盖或合并项目。
- 本地审核状态不可信；导入的译文一律创建为草稿。请求需携带预览摘要，应用后重复提交同一用户和本地项目 ID 返回原服务端项目；同一 ID 对应不同包内容拒绝。
- 迁移应用为持久化异步任务并分批写入；任务状态可查询、失败可用原包恢复重试。迁移期间项目对日常工作不可见；同一 Owner 名下项目名称去除首尾空格后大小写不敏感且唯一，预览冲突时必须显式改名。
- 每个项目至少配置一个目标语言；源语言在项目创建后固定，目标语言可恢复归档但不能归档最后一个活动目标语言。所有语言标签采用有效 BCP 47。
- 只有没有活动词条的命名空间可归档和恢复。Owner/Admin 可移动词条，词条 ID、译文和审核状态不变。
- 术语对同一项目/源语言/目标语言/源词只有一个首选译法；按大小写不敏感连续子串匹配并优先展示较长术语。相同源文可能有多个翻译记忆候选，均展示来源键且不自动应用。

## 阶段门槛

- **阶段 A（产品和接口）**：角色矩阵、状态机、格式范围、质量规则、迁移策略已确认并记入 ADR；租户隔离与 Outbox 本期明确排除。OIDC 提供者由部署配置；OpenAPI 契约仍需发布。
- **阶段 B（持久化和迁移）**：真实数据库迁移、组织/项目/词条 API、访问控制、前端数据适配器和原型迁移；通过 B01–B04、B12 对应集成测试。
- **阶段 C（协作和交付）**：译文、校验、术语/记忆、异步导入、发布与历史；通过 B05–B10 对应集成测试。
- **商业试用门**：B01–B12 都有真实执行证据，并满足 `GOAL.md` 的并发、性能、安全、运维与恢复门槛。设计文档、模拟数据或单元测试不能替代端到端证据。
