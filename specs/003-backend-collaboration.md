## 产品范围

首期范围：项目成员与角色权限（暂不引入租户/组织隔离）、项目和语言、命名空间与源词条、译文协作与审核、占位符/必填校验、术语与翻译记忆建议、JSON 导入预览和异步导入、质量门禁、不可变发布版本、JSON 与 Java Properties 导出、历史回溯、审计与运维所需的健康/任务状态接口。

发布消费端通过单独的 Spring Boot Starter 同步最新已发布快照；公开接口仅提供发布元数据和不可变文件，不需要身份认证。Starter 校验 SHA-256 后原子替换内存快照，拉取、校验或解析失败时继续提供上一个有效快照。该公开读取面不改变工作台 API 的 OIDC 身份认证和项目权限规则。详见 [ADR-0008](../docs/adr/0008-published-translation-consumer.md)。

消费端同步方式需要通过配置切换：普通 HTTP 轮询作为默认/兜底，并同时支持 Netty TCP 长连接实时通知和 WebSocket 实时通知。两种长连接只推送发布版本元数据变化，消费端收到通知后仍通过 HTTP 拉取完整不可变快照并校验 SHA-256。消费流量是单向通知，因此 WebSocket 不承载任意业务命令；Netty 模式使用独立 TCP 监听端口和 newline-delimited JSON 订阅协议。

机器翻译纳入首期主流程，但不默认启用外部服务：通过配置 LibreTranslate-compatible 或 OpenAI-compatible Chat Completions HTTP provider 接入自托管/托管翻译服务、大模型 API 或兼容第三方网关。任务异步持久化、可查询/重试；结果只以草稿回填，且必须匹配创建时源版本和译文版本、当前译文仍为空，避免旧任务覆盖人工编辑。未配置 provider 时，新建任务和重排失败项均返回服务不可用，不把无人处理的项目重新入队。Git 集成、截图/OCR、计费商城、微服务拆分和跨区域主动-主动部署不纳入首期。

## DDD 规则摘要

- 组织、项目、目录/词条、译文、导入任务、发布版本分别有清晰生命周期；不以一个巨型 `Project` 聚合承载所有词条和译文。
- `CatalogEntry` 管源文本与单调递增的源版本；每个 `(entry, targetLocale)` 对应独立 `Translation` 聚合，含翻译状态、审核状态和乐观锁版本。
- 任一源文本变更使该词条全部目标译文转为 `NEEDS_REVIEW`，并留下源版本变更事件；译文更新必须带期望版本，冲突返回可恢复的 409。
- 审核是针对具体译文版本的不可变决定；被编辑的新版本撤销原审核有效性，审核人不能审核自己的译文（管理员代审需明确审计原因）。
- 发布版本是不可变快照，记录词条源版本、译文版本、质量报告、操作者与资源校验和；回滚创建指向旧内容的新发布，不改写历史。
- `Release` 领域聚合判定可发布译文资格：内容必须非空、已审核、基于当前源文版本且命名占位符语法/名称/次数正确；翻译质量与发布共用 `quality.PlaceholderRules`，应用服务只编排授权、任务、序列化和持久化。
- 每个命令先验证项目成员权限和领域不变量；本期没有组织租户上下文，不接受客户端伪造租户 ID 来代替授权。
- 项目成员在整个项目内仅有一个角色；Owner/Admin 管理设置，Translator 编辑译文并送审，Reviewer 审核，Viewer 只读；Admin 不能管理 Owner/Admin，Owner 只能转让给现有 Admin。
- 项目、语言、命名空间和词条可恢复归档且不硬删除；源语言不可改，目标语言可归档但至少保留一个启用目标语言。旧发布保持不可变并继续供有权限成员下载。
- 词条键在项目范围唯一，命名空间只是分组。显式改键/移动保留词条 ID、译文状态和源修订；扁平文件导入不推测改键。
- 首期质量规则只接受命名占位符 `{name}`，按名称和次数精确对比；`{{`/`}}` 是字面花括号，不支持的花括号格式视为错误。错误阻止送审和发布，但允许保存草稿。
- 扁平 UTF-8 JSON 是导入格式；扁平 JSON 和 Java Properties 是发布格式。Properties 只导出，稳定排序并转义为 ASCII，不保留注释。
- 术语和翻译记忆属于独立语言知识模块且按项目隔离；记忆建议限同项目当前源版本的已审核完全匹配结果，仅供选择，不自动写入。

## 当前后端实现范围

当前代码建立了通用 OIDC JWT 身份解析、项目成员角色授权、Workspace、Catalog、Translation、Import、Release、AuditLog 模块及 `/api/v1` REST API。前端支持显式 API 模式、OIDC 登录、项目与成员管理、译文保存/送审/通过/退回及状态筛选；译文详情返回最新审核决定和退回原因，译者可在编辑界面查看反馈及最近 100 条修订快照；源文修改/历史/归档、术语与翻译记忆建议、JSON 差异预览与异步导入、异步发布状态与重试、可跨会话查询的发布任务历史、发布历史查询/下载/回滚以及 JSON/Java Properties 发布；发布历史校验和元数据不包含完整资源正文。未配置服务端时保留本地原型。已加入版本 1 的本地项目迁移包预览、确认、幂等异步分批迁移、进度和本地/服务端词条 ID 映射查询，以及迁移失败后同包重试；迁移期间项目保持隐藏。服务端提供公开 liveness/readiness 探针，readiness 检查 MySQL 连通性且不公开组件详情。隔离 MySQL 8.0.46 实例已成功执行 Flyway V1–V9 并启动应用，`/readyz` 返回 `UP`；使用本地 RS256 测试身份和协议 stub 对真实 API/数据库完成机器翻译、人工审核和发布导出闭环。GitHub Actions 已在 MySQL 8.0.46 上成功运行 Flyway V1–V11、MyBatis 查询及 schema 注释/索引检查；最新 CI 完整通过，包含归档项目成员读取历史且禁止写入/发布的 MySQL 集成用例。消费端 MySQL HTTP 快照路径已在 MySQL 8.0.46 CI 中通过。新增 Netty/WebSocket MySQL 集成路径调用 `ReleaseApplicationService.publish` 生成真实 MyBatis 发布快照；事务提交后两个长连接通知新校验和，匿名 HTTP 拉取正文并校验 SHA-256。MySQL 8.0.46 CI 已通过；该集成调用应用服务而非发布任务 HTTP/UI 入口。真实部署 OIDC、外部翻译服务、多实例/规模并发和正式备份恢复演练仍未验证。租户模式和 Outbox 本期不实现。

Workspace 生命周期切片已补齐：项目创建默认配置一个目标语言并接受描述；项目和目标语言可归档/恢复（至少一个活动目标语言），归档项目在成员列表可见且可读历史；成员角色可调整/移除/主动离开，Owner 可转让给现有 Admin；Owner/Admin/Translator/Reviewer/Viewer 规则由 Project 聚合校验，项目归档与成员操作写审计。后端 37 项测试（含 Spring Modulith 边界检查）与前端生产构建通过；V6 已在隔离 MySQL 8.0.46 的 V1–V9 执行中验证，双用户授权矩阵与归档并发仍需专项验收。

词条生命周期补齐恢复入口：Owner/Admin 可在活动命名空间内筛选归档词条并恢复；归档词条仍保留源文案、译文和历史，恢复前必须先恢复其命名空间。`CatalogEntry` 领域对象负责归档/恢复状态转换并递增目录版本，应用服务持有活动命名空间锁后协调 MyBatis 持久化，操作写入审计。后端应用服务、MyBatis 查询/API 与工作台入口已实现，MySQL 8.0 实例验证仍待执行。

JSON 导入任务工作台可读取项目最近 20 项任务，查看新增/更新/未变化/冲突统计与安全失败摘要；可继续确认尚未应用的预览，并重试失败任务。同一项目内并发使用相同幂等键和相同数据时返回唯一获胜任务；同键对应不同内容、命名空间或语言时返回冲突。最近任务接口只选择状态、时间和汇总字段，不返回导入正文或差异内容。API 模式文件上限与服务端统一为 5 MiB，本地原型仍保留 1 MB 限制。MySQL 8.0 新增最近任务索引和 JSON 汇总查询，需在实例执行迁移及查询后才能算数据库验收通过。

发布消费端 B14 已有匿名只读的 latest 元数据/内容 API，以及独立 `integrations/yandu-translation-spring-boot-starter` Maven artifact。Starter 支持 JSON Flat v1 与 Java Properties v1，下载前读取元数据、校验 SHA-256 后原子替换内存快照；失败时保留旧快照并重试。B15 的 Netty TCP 与 WebSocket 服务端通知和可配置客户端已实现；各传输客户端位于单独 Maven 模块，基础 Starter 不引入 Netty。后端包含真实 Netty socket 和 WebSocket handler 测试，消费者 Netty/WebSocket 模块均有本地协议测试。上述 API 与同步查询尚未在 MySQL 8.0 实例验证，artifact 尚未发布到公共 Maven 仓库。

机器翻译通过可配置 HTTP provider 纳入主流程，支持 LibreTranslate-compatible `/translate` 及 OpenAI-compatible Chat Completions（可接大模型 API 或第三方兼容网关）。provider port、LibreTranslate 实现与 OpenAI-compatible 实现位于独立 Maven 模块；部署构建显式选择 provider 模块，再设置 `YANDU_MT_PROVIDER`、`YANDU_MT_BASE_URL`，大模型还需 `YANDU_MT_MODEL`；必要时设置服务端 `YANDU_MT_API_KEY`。未引入实现或未配置 provider 时返回 503，不创建任务。可为当前目标语言创建幂等异步任务，最多四个 worker 并发执行，按词条展示进度/失败并重试；空 provider 结果记录为失败，不创建空译文；有效结果只写入草稿，回填时锁源词条并比较源修订、译文版本和空值，版本变化或人工已译时跳过。MySQL 8.0.46 上 V1–V9 已执行；本地数据库端到端 API 流程验证了幂等创建、机器结果草稿回填、人工修订/审核和发布导出，协议 stub 下人工编辑与源版本竞争均安全跳过。真实外部 provider 调用、部署 IdP 和多实例并发仍未验证。

发布门禁位于 `release.domain.Release`：工作流应用服务取得项目/语言下的当前词条投影后，由领域聚合校验译文非空、审核通过、源版本匹配和命名占位符一致，再由应用层负责格式序列化、校验和及快照持久化。历史代码曾仅依赖“已审核”状态而未独立拒绝空白存量译文；该边界现已补齐。JDK 21 下后端全套 72 项测试及 Spring Modulith 边界检查通过；本次领域调整未改 MySQL SQL，但没有重新运行 MySQL 8.0 发布集成流程。

工程取舍：优先沿现有模块扩展，不为单一小操作拆出一组类型或单独测试类。用例验证按大模块集中执行；小改动先做编译和差异检查，避免频繁运行全套测试。

### B12 本地项目迁移约定

- 迁移包为 UTF-8 JSON，`format` 固定为 `yandu-project-migration`，`schemaVersion` 为 `1`；一次仅迁移一个项目，包含项目名称、说明、源语言、目标语言和词条/各语言译文。
- 预览校验包大小不超过 5 MiB、词条数不超过 10,000、语言和词条规则符合当前服务端约束，并返回名称冲突及可修正的目标项目名称。
- 应用始终创建新服务端项目；服务端重新生成所有数字 ID。词条键冲突或格式错误拒绝整个包，不自动覆盖或合并项目。
- 本地审核状态不可信；导入的译文一律创建为草稿。请求需携带预览摘要，应用后重复提交同一用户和本地项目 ID 返回原服务端项目；同一 ID 对应不同包内容拒绝。
- 迁移应用为持久化异步任务并分批写入；任务状态可查询、失败可用原包恢复重试。迁移期间项目对日常工作不可见；同一 Owner 名下项目名称去除首尾空格后大小写不敏感且唯一，预览冲突时必须显式改名。
- 每个项目至少配置一个目标语言；源语言在项目创建后固定，目标语言可恢复归档但不能归档最后一个活动目标语言。所有语言标签采用有效 BCP 47。
- 只有没有活动词条的命名空间可归档和恢复。Owner/Admin 可移动词条，词条 ID、译文和审核状态不变。
- 命名空间可由 Owner/Admin 创建、重命名、归档和恢复；归档会在数据库事务中校验无活动词条。新建词条与导入必须使用活动命名空间，归档与创建并发时通过命名空间行锁避免归档后仍写入。Owner/Admin 可改键或移动词条；译文身份与审核状态保留，源文修订不递增，目录版本递增并记录审计。词条键在项目内唯一，迁移前用 SQL 检查已有重复键；重复数据须先人工消歧。
- 术语对同一项目/源语言/目标语言/源词只有一个首选译法；按大小写不敏感连续子串匹配并优先展示较长术语。相同源文可能有多个翻译记忆候选，均展示来源键且不自动应用。
